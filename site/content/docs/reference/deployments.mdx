`Supported` networks are ready for their stated environment. `Experimental` networks are under
qualification. `Beta` networks use real funds and irreversible state while ABX remains pre-1.0.
The CLI refuses disabled networks.

Before a production transaction, run the same flow on the paired testnet. Review the network, signer,
transaction group, value, and locks. ABX has not had an independent third-party audit.

The machine-readable sources of truth are
[`chain-support.json`](https://github.com/ArtBlocks/abx/blob/main/packages/sdk/src/chain-support.json)
for network status and paired networks, and
[`deployments.ts`](https://github.com/ArtBlocks/abx/blob/main/packages/sdk/src/deployments.ts) for
addresses. The live service descriptor decides sponsorship availability. Machine-readable data wins
if this page differs.

A dependency registry is separate from the token and factories. A collection may set its own registry
until it locks dependencies. Adding a registry later does not require a new token deployment.

## Contract generations

`abx-core-v3` is current for new deployments.

`abx-core-v2` remains supported for existing collections: reads, writes, indexing, and serving stay
enabled. New deployments use v3. The append-only generation registry in the SDK contains the six v2
factory addresses for provenance and compatibility.

## Verify a project

```bash
abx verify 0xYourContract
abx state 0xYourContract
```

Canonical status comes from a factory's `isAbxClone` record. The SDK also reports older known factory
generations as provenance without treating them as current trust anchors.

`abx verify` also compares the collection's metadata renderer and generator with the current
addresses. A prior or custom singleton reports `not current`; the manifest does not classify it as
broken.

All listed Solidity contracts have public exact-match source verification. A canonical address
without an exact source match is a release bug.
