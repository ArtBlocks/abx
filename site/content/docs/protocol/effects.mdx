title: "Effects"
description: "Derived output produced from ABX events and token state."
---

An effect is an offchain process that watches project events and writes derived output. Rendering a
code project to a still image is the reference effect. Effects never hold source files.

## Addressing

An effect declares a key, triggers, outputs, and an environment. ABX hashes the content, canonical
token data, and environment ID into `inputsHash`.

```text
{chainId}/{address}/{tokenId}/{effectKey}/{inputsHash}/{outputKey}
```

The address makes deterministic work idempotent. A restarted worker can ask storage what is missing.

## Triggers

| Change | Event |
| --- | --- |
| Mint | `Transfer` from zero |
| Parameter value | `TokenParamConfigured` or `ContractParamConfigured` |
| Parameter schema | `ParamSchemaConfigured` |
| Owner-sensitive output | `Transfer` |
| Manual render | Operator request |

## Metadata binding

`render.image` fills `image` only when the project did not set one. `render.traits` merges into
`attributes`, with onchain traits winning duplicate names. Other outputs appear in the artifact list.

A worker may post a hash or locator back to an authorized parameter and lock it later. Write-back is
optional.

The reference worker loads the live document in Chromium, waits for `abx.done()` or a configured delay,
and captures the image and traits. Run it with `abx effects`, `abx render`, or `abx deploy-effects`.

Renderer capabilities are deployment properties, not protocol guarantees. A service may advertise
`render.constraints.hardwareAcceleration` and `render.constraints.maxCaptureDelayMs` in its service
descriptor. Inspect them with `abx remote <name|url>` before relying on a managed renderer.

The managed ABX renderer is CPU/headless and does not provide GPU/WebGL hardware acceleration. The
default `abx deploy-effects` Playwright container also does not guarantee a GPU merely because it is
self-hosted. Projects that require hardware acceleration need an effects worker deployed on tested,
GPU-capable infrastructure.

For software-compatible projects, call `abx.done()` only after the intended frame and traits are
ready. A bounded `render.captureDelay` can cover slow initialization, but cannot make unavailable GPU
features available. A current artifact confirms that bytes were published for the current state; it
does not prove the image is visually correct.

## Publishing externally rendered outputs

A creator may render images and traits on their own infrastructure and publish them to ABX Services
through the authenticated `POST /v1/effect-artifacts` route. The project must be registered to the
publishing account. This applies to supported mainnet and testnet chains, including projects whose
capture needs hardware acceleration unavailable in the managed renderer.

Publish `render/image` as a public `locator` and `render/traits` as JSON in `bytes_base64` (at most
64 KiB). Include the chain, collection, token ID, and the `inputsHash` computed from the complete
settled token data. The producer retains custody of image bytes; the resolver holds the bound traits.

ABX Services stores separate input-state versions so a stale publication cannot replace a current
one. Explicit republishing can replace the output at the same hash. Managed captures preserve an
existing publication at that hash. An explicit on-chain image field together with current published
traits satisfies both outputs without requiring another managed capture. Retained artifacts are
service data, not an archival guarantee; keep source inputs and copies of externally produced output.

Data-backed parameters require successful RPC reads of their bytes. Hosted rendering refuses an
incomplete or commitment-mismatched input, and hosted read routes return a retryable error when they
cannot establish currency rather than declaring a hash-only fallback current.

## Checking currency directly

`abx artifacts <address> --token <id>` reads a token's artifact set without fetching and parsing the
whole served document. It reports the same entries the metadata would serve, plus every registered
effect row, current and stale, labeled against the token's active `inputsHash`. A stale row (a
parameter changed since it rendered) is silently absent from the served `artifacts` list, but stays
visible here so a param change that re-addressed a render is diagnosable rather than invisible.

`--remote <name|url>` reads the hosted resolver instead of this node's local projection. The report
identifies which service answered.

## Reference worker deployment limits

The reference worker is for one trusted operator's collections. It does not provide a multi-tenant
sandbox. Rendering uses a fresh browser context and a checked HTTP proxy: public network dependencies
remain available; private network destinations are refused. The configured resolver origin is an
operator-owned exception so a co-located local resolver remains usable. Rendering uses proxied web
traffic; non-proxied WebRTC UDP and QUIC are disabled. Collector browsers retain their own behavior.

Without `ABX_EFFECTS_TOKEN`, the HTTP trigger server listens on `127.0.0.1` only. A public listener
(`ABX_EFFECTS_HOST=0.0.0.0`) requires a nonempty token. Generated container deployments select that
public mode and refuse to start without the token. `/health` remains public; `/run` and `/notify`
require `Authorization: Bearer <token>` in public mode. `--once` needs no HTTP listener.

Trigger requests use `Content-Type: application/json` and accept bodies up to 1 MiB. Tokenless local
mode also checks the request Host and refuses other browser origins. Existing CLI commands supply
JSON automatically; a custom browser control panel must use the runner's own origin or an
authenticated integration.

For deterministic cloud thumbnails, the on-chain `image` URL template must select an object under
`<publicBase>/<chainId>/<lowercase-contract-address>/`, for example
`https://cdn.example/8453/0x0000000000000000000000000000000000000001/{id}.png`.
`abx deploy-code --image-base` and `abx deploy-edition-code --image-base` add the namespace
automatically, resolving the factory-predicted collection address before signing.
Templates outside that collection namespace are rejected before rendering. Existing self-hosters
using a custom prefix must update their image template to receive further deterministic thumbnail
writes; existing stored objects are not moved or deleted automatically.

The reference render effect refuses image and trait outputs when the live document raises an
uncaught exception or the page crashes before capture completes. Console diagnostics alone do not
fail a render. Healthy scripts without `abx.done()` retain the bounded capture-delay fallback.
