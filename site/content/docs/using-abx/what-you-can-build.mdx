ABX is not only for generative art. Art is one use among many. An ABX project can also be a website,
a game, a community space, a record, or a mechanism that acts on other onchain protocols.

Every ABX project is a standard ERC-721 or ERC-1155 contract on an EVM chain, so wallets,
marketplaces, and indexers already understand it. What makes it programmable is what the contract can
hold and do: files and code, typed values that change over time, rules that run when a value changes
or a token moves, and reads from other contracts on the same chain.

## Starting points

| Build | How ABX supports it | Read more |
| --- | --- | --- |
| Websites, archives, and preserved files | ABX FS stores files and whole directories onchain, with publishing history and owner-controlled locks. A token can present a static site, a dapp, or an archive. | [ABX utilities](/docs/using-abx/guides/utilities) |
| Interactive apps and games | A code project stores a program onchain or points to one. Each token runs it with its own seed and current values. | [Code projects](/docs/protocol/code-projects) |
| Objects with state and rules | Typed parameters hold values that the creator, the token's holder, or a named address may change. Hooks can reject an edit, allow a value only to increase, or make a token non-transferable. | [Parameters](/docs/protocol/params) |
| Onchain actions | A parameter edit or a transfer can trigger contract calls: swap through an AMM router, create another asset, or settle an obligation. | [Custom mechanics](/docs/using-abx/guides/custom-mechanics) |
| Protocol and community integrations | Solidity renderers and augment hooks read same-chain state, such as a pool, a treasury balance, or a community token. A companion ERC-20 can be launched with another protocol's tools. | [Ecosystem integrations](/docs/using-abx/guides/ecosystem-integrations) |
| Records, claims, and provenance | Metadata fields can be stored, computed, or committed by hash, then locked. Every change emits an event that anyone can replay. | [Metadata](/docs/protocol/metadata), [Events](/docs/protocol/event-spine) |
| Datasets, models, and source files | A token can anchor named files beyond its marketplace image, such as source files, print exports, models, datasets, or audio stems. | [Artifacts](/docs/protocol/data-plane) |
| Art, including generative art | 1/1s, image series, editions, and code projects, with onchain or offchain storage. | [Choose a project](/docs/using-abx/guides/deploy-a-digital-asset) |

## Projects built on ABX

- [ABXdoku](https://github.com/ArtBlocks/ABXdoku) is a fully onchain daily Sudoku. Every token turns
  over to a new puzzle each UTC day with no transaction, scheduler, or server. Its source is a
  complete reference project.
- [coinspace](https://coinspace.social) is a community where you make a page and own it.
- [Sprite Party](https://www.spriteparty.com/) by Generative Goods is an event guestbook where every
  guest shows up as a pixel sprite.

## Start with the idea

Describe what the object is for, who takes part, what changes over time, and who may change it.
Appearance and deployment shape come later. The [ABX skill](/docs/using-abx/agent-and-skill) has the
agent explore concepts with you and wait until you choose one before building.

Some prompts to adapt:

- "Help me publish my project's documentation site onchain with ABX FS."
- "Help me make a guestbook for my event where every guest gets a token."
- "Help me design a membership pass whose level can only go up and that cannot be transferred."
- "Help me make a daily puzzle that changes at midnight UTC without a server."
- "Help me make an object whose look follows our community treasury's balance."

## Know the limits

- These are patterns, not ready-made features. Custom rules and onchain actions run in a controller
  contract you write and test on a testnet or fork.
- Parameters and hooks exist only on code projects created with `abx deploy-code`. An image series
  cannot add them later.
- A token can represent rights or a financial instrument, but real-world rights, custody, and
  enforcement need their own legal and operational design.
- Storing a program onchain does not preserve the services it calls. Each runtime dependency needs
  its own plan.
