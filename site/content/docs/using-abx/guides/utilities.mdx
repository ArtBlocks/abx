ABX utilities add capabilities through their own official tools and interfaces. Discover them without
installing any utility package:

```bash
abx utils
abx utils abxfs --json
abx capabilities --json
```

The same utility descriptors appear in capability output. These commands provide package and
documentation references; they do not install or run another CLI.

## ABX FS

[ABX FS](https://fs.abx.io) stores content-addressed files and directories on-chain with compression.
Its ABX-based project layer adds ownership, publishing history, and tags. It can preserve a static
website or dapp, NFT assets, project documentation, or other digital work. Content can exist without
a project token, and an ABX collection can use FS content independently of the FS project's identity.

Install only what the project needs:

```bash
pnpm add --save-dev @artblocks/abxfs-cli
pnpm exec abxfs --help
# For programmatic integration:
pnpm add @artblocks/abxfs-sdk
```

The [ABX FS documentation](https://docs.fs.abx.io) maintains command syntax, package interfaces,
deployed contracts, and limits. FS uses its own chain and signing configuration. Inspect its help
and registry; ABX signing flags and chain settings do not automatically apply to it.

## Preserve the work and choose its delivery

FS content stays on the network where it was stored. The preferred delivery method is a separate
choice:

| Experience | Preferred route |
| --- | --- |
| Suitable self-contained media or HTML | Auto selects an embedded data URI after inspection |
| Multi-file website or larger content | A chain gateway serves the preserved bytes over HTTP |
| Creator explicitly maintains IPFS availability | Opt-in IPFS presentation with creator-managed pins |

A data URI contains one resource, so relative sibling files do not acquire a directory origin.
An existing build process can produce self-contained HTML where appropriate. Runtime network
dependencies still need inspection: uploading JavaScript does not preserve every service it calls.
“Fully on-chain” describes the source bytes and resolution, while the browser executes the experience.

The chain gateway is the straightforward default when embedding is unsuitable. A gateway is an
off-chain delivery dependency, even though its content can be reconstructed from chain. IPFS adds a
content-derived distribution address, with continuing pinning and gateway availability requirements;
Auto does not select a paid provider or create pins.

Presentation controls `animation_url`, which is commonly used by marketplaces. Auto is a one-time
tooling choice that saves Embedded or ChainGateway; it does not become an on-chain mode. Inspect
the selected file or entrypoint. A directory may display `index.html` or another selected file.
For Embedded, a blank directory path reads its `index.html`; without it, the result is inert text,
not a directory listing. The [FS native read interface](https://docs.fs.abx.io/docs/reference/presentation)
documents direct Solidity reads and the fixed ABX adapter. Auto selects the gateway when there is no
suitable displayed file, and the gateway can show a navigable directory listing. Explicit Embedded does not silently
switch to HTTP when reading fails.

The current presentation renderer imposes no product byte ceiling. Large content can still exceed
the gas, memory or time budget of an EVM/RPC read. Inspect the complete `tokenURI` result rather
than assuming a successful file read proves that every consumer can resolve the metadata.
Auto's size and dependency recommendations belong to the utility tooling and can evolve.

New uploads and first publication into an empty token can use Auto or an explicit method. Updates
preserve the saved presentation unless a change is requested. Review whether an update replaces the
whole project or applies draft/overlay operations: replacement removes omitted paths; an overlay
preserves untouched files. A presentation-only failure after publication needs presentation recovery,
not another mint or publish.

Presentation-capable project generations support changing methods and independent irreversible locks
on displayed content, delivery method, and endpoint configuration. Locking content fixes its concrete
root and entrypoint; later publications and tag movements do not change that displayed source.
Other project metadata and publishing history can still change. Freezes are one-way and survive
ownership transfers. This makes fixed content with replaceable delivery
possible. Endpoint locks do not guarantee endpoint availability. Review the exact lock and its scope
before signing, and preserve endpoint flexibility unless a creator deliberately chooses otherwise.

Existing orgs keep the factory and renderer they were created with. Inspect the FS registry and
deployment documentation for supported generations and any explicitly retired test generation.
New-project defaults use the current factory; a software update does not upgrade an existing token.

## Connect FS content to an ABX project

For a minted ABX 1/1 with on-chain token metadata and a writable `animation_url`, choose how the
browser will receive the FS content. On-chain storage of the bytes is independent of delivery.

For self-contained EVM-readable HTML on the same chain, prefer the official fixed-source adapter for
the root and entrypoint using the [FS reader reference](https://docs.fs.abx.io/docs/reference/presentation).
Set `ADAPTER` to that deployed contract and encode it as both reader and pointer.

```bash
READER_VALUE=$(cast abi-encode 'f(address,address)' "$ADAPTER" "$ADAPTER")
ABX_CHAIN=base-sepolia abx set-field "$TOKEN" --token 0 --field animation_url --representation reader --value "$READER_VALUE" --sign
ABX_CHAIN=base-sepolia abx tokenuri "$TOKEN" --token 0 --json
```

Check that `animation_url` is an HTML data URI that decodes to the expected file.
Keep the adapter's codec and read limits in mind. Verify the complete `tokenURI` within the
RPC budget used by the intended consumer.

Use an HTTP gateway when the experience needs a browser origin for sibling files or the reader
cannot serve the payload. Set `ABX_CHAIN` for the ABX token's network. The gateway URL
includes the network where the FS content was stored.

```bash
ABX_CHAIN=base-sepolia abx set-field "$TOKEN" --token 0 --field animation_url --url "$FS_GATEWAY_URL" --sign
ABX_CHAIN=base-sepolia abx tokenuri "$TOKEN" --token 0 --json
```

Use the public FS URL returned by the FS tooling as `FS_GATEWAY_URL`. In `tokenuri`, check that
`animation_url` contains the exact locator. Serving depends on that gateway remaining
available. For an attachment that should appear in a resolver's artifact list, use `abx attach`.

A preserved website does not itself supply a mutable backend, an indexed attachment list, or a
marketplace thumbnail. Choose those surfaces deliberately using the [storage guide](/docs/using-abx/guides/storage)
and [deployment guide](/docs/using-abx/guides/deploy-a-digital-asset).
