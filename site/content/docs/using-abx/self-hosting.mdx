title: "Self-host"
description: "Run the ABX resolver and effects worker on your own infrastructure."
---

ABX ships a resolver and an effects worker. Neither needs an onchain signing key.

The reference toolkit supports collections controlled by **one trusted operator**. It is not a
supported multi-tenant host for unrelated creators. Running third-party programs requires additional
worker isolation, resource controls, and network and credential separation. Content subdomains protect
browser origins; they do not make the reference worker a complete sandbox. Use a managed provider
that explicitly supports third-party creators for that use case.

Project-controlled server fetches accept public HTTP(S) destinations. Private, loopback, link-local,
and reserved network addresses are refused, including DNS answers and redirect hops. Entry documents
have a 16 MiB decoded response limit, a 10-second fetch deadline, and a five-redirect limit; only documents up to 1 MiB enter
the 32-entry cache. These are host limits, not restrictions on ABX contracts or on collectors' browsers.
A refused destination is not fetched by the server or converted into an unsafe fallback.

`abx preview` and browser-wallet signing listen on loopback only. Preview assets must stay inside the
build directory after symlinks are resolved, and hidden files are not served. Put required assets
inside the build root rather than linking to files elsewhere. Signing links contain a temporary
session secret: open the exact link the CLI prints, and do not publish it. The browser-signing lane
verifies direct EVM transactions; wrapped smart-account and multisig workflows use `--unsigned`.

## Local data directory

ABX stores its SQLite projection, managed Arweave key, and content index together. It chooses one
directory per command:

1. `ABX_DATA_DIR`, when set.
2. `.abx-self-host` in the current directory, when present.
3. For read-only commands, the nearest `.abx-self-host` above the current directory.

Writes use the first two rules only. If neither matches, they create `.abx-self-host` in the current
directory. Reads print the path when they find state in a parent directory.

```bash
cd my-project/contracts/src
abx status                  # reads my-project/.abx-self-host
abx add 0xSomeOtherContract # creates ./.abx-self-host here
```

## Resolver

Run it locally:

```bash
abx serve
```

Deploy it to a supported host:

```bash
abx deploy-resolver --provider <fly|render|vps>
```

The resolver replays events, stores project state, and watches for new blocks.

| Route | Result |
| --- | --- |
| `/t/{chainId}/{address}/{tokenId}` | Token metadata |
| `/c/{chainId}/{address}` | Collection metadata |
| `/api/project/{address}` | Reconstructed project state |
| `/d/{chainId}/{address}` | Project dashboard |
| `/health` | Service health |

Set `ABX_RESOLVER_ADMIN_TOKEN` on the host to enable registration and reindexing. Keep the same value
locally as `ABX_REMOTE_SELF_TOKEN`. It controls the index and cannot sign transactions.

Check progress with `abx status`. The five states are `queued`, `backfilling`, `live`, `stale`, and
`failed`.

```bash
abx status
abx status 0xYourContract
```

The reference resolver assumes one trusted operator. Do not share it with unrelated customers without
adding tenant isolation, quotas, and rate limits.

## Content origins

Project HTML and other active documents must execute separately from the resolver dashboard and
control plane. By default, the reference resolver serves publisher documents with an opaque-origin
CSP sandbox. Scripts and embedding remain enabled, but persistent browser storage and some wallet
connections require a dedicated content domain.

For complete websites, configure a separate domain with wildcard DNS and HTTPS pointing at the
resolver, then set on the resolver and its effects worker:

```bash
ABX_CONTENT_DOMAIN=content.example.net
```

Each token's live application is served at `https://t-{digest}.content.example.net/`, with query
parameters and fragments preserved. The digest is the full SHA-256 of the canonical UTF-8 string
`abx-content-v1:token:{chainId}:{lowercaseAddress}:{decimalTokenId}`, encoded as lowercase, unpadded
RFC 4648 base32. The complete label is 54 characters even for the largest uint256 token ID. Use the
SDK's `contentOriginLabel` or discovery helper rather than implementing a provider's hostname policy
in artwork. Token artifacts retain their protocol paths on that token's origin. Collection artifacts
use a separate `c-` origin (the hash preimage is `abx-content-v1:collection:{chainId}:{lowercaseAddress}`).
A content host refuses other tokens, account, dashboard, and control routes. Keep application
sessions and sensitive cookies off the dedicated domain: sibling origins separate DOM and storage,
but parent-domain cookies can be shared. Token editions share an origin for all copies of one ID.

Existing `/a/` URLs and the older `{chainId}-{address}` collection hosts remain entrypoints:
top-level browser navigation redirects to the token origin; frames and server-side downloads receive
a restricted marketplace wrapper. Image and artifact routes redirect without changing committed
bytes. The response's canonical `Link` header identifies the direct URL. Service descriptors advertise
`content.domain`, `content.scheme`, and `content.liveViewUrlTemplate`; `abx remote` displays these.
SDK clients can use `discoveredLiveViewUrl` to expand a provider's template or fall back to `/a/` for
an unknown scheme. Fallbacks retain the configured resolver path prefix; a descriptor’s diagnostic
base URL does not override that transport. Do not infer token coordinates from the browser path; use the ABX runtime's token
identity. Relative resources must be valid at `/` or use explicit URLs.

The SQLite index stores a disposable reverse lookup for token hashes, backfills existing projections
on startup, and maintains it during indexing. An independently hosted resolver can rebuild the same
URLs from chain state without this provider's database. Unknown hashes and unavailable tokens fail
with the same lifecycle rules as `/a/`. No inventory of possible unminted IDs is generated.

Keep contract-facing token and collection URI bases on the resolver (`https://resolver.example/t`
and `https://resolver.example/c`). Contracts append their chain/address/token coordinates; the
content domain is a browser delivery layer, not a replacement metadata base. This also applies to
on-chain applications that fetch HTTP resources: discover their canonical URL or follow the resolver
entrypoint. Fully on-chain URI renderers still return their own data documents; external IPFS,
Arweave, or creator-hosted URLs retain those hosts' security policies. This resolver cannot impose
HTTP isolation on documents served elsewhere or directly embedded as data URIs.

For local development, use `ABX_PUBLIC_BASE_URL=http://127.0.0.1:8787` with
`ABX_CONTENT_DOMAIN=localhost:8787` for HTTP token subdomains on the same port. The `localhost` root
remains a public alias for local control reads. Use HTTPS for public domains and configure wildcard
DNS and certificates before enabling the setting. Moving to a new origin resets browser storage and
may require a fresh wallet connection. Without a content domain, opaque-origin sandboxing prevents
shared-origin DOM access but limits storage and wallet integrations; do not remove that sandbox to
make untrusted multi-project hosting work. Provider-specific embeds that copy artwork into their own
origin must supply their own sandbox and isolation.

## SQLite maintenance

The projection lives at `.abx-self-host/index.db`. Check and reclaim unused pages with:

```bash
abx vacuum
abx vacuum convert
abx vacuum incremental [--pages n]
```

`abx serve` runs bounded incremental cleanup between watch cycles. `abx vacuum convert` is a manual,
one-time full rewrite for an older database with `auto_vacuum: none`. It may need twice the database's
disk size. Run it only when `abx vacuum` recommends it.

## Effects worker

The effects worker uses Chromium to render images and traits for code projects.

```bash
abx effects
abx effects --once
abx render 0xYourContract
abx deploy-effects --resolver-url https://metadata.example.com
```

Set `ABX_EFFECTS_URL` on the resolver for immediate notifications. The worker also sweeps for missed
work.

Separate services need shared storage such as S3/R2, IPFS, or Arweave. Filesystem storage works only
when both processes share the disk. See [Storage](/docs/using-abx/guides/storage).

## Move hosts

```bash
abx migrate 0xYourContract --from <old-resolver> --to <new-resolver>
```

The migration copies offchain values, verifies hashes, and compares results. It does not change DNS
or send a transaction.
