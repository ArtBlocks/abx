---
title: "Self-host"
description: "Run the ABX resolver and effects worker on your own infrastructure."
---

ABX ships a resolver and an effects worker. Neither needs an onchain signing key.

## Local data directory

ABX stores its SQLite projection, managed Arweave key, and content index together. It chooses one
directory per command:

1. `ABX_DATA_DIR`, when set.
2. `.abx-self-host` in the current directory, when present.
3. For read-only commands, the nearest `.abx-self-host` above the current directory.

Writes use the first two rules only. If neither matches, they create `.abx-self-host` in the current
directory. Reads print the path when they find state in a parent directory.

```bash
cd my-project/contracts/src
abx status                  # reads my-project/.abx-self-host
abx add 0xSomeOtherContract # creates ./.abx-self-host here
```

## Resolver

Run it locally:

```bash
abx serve
```

Deploy it to a supported host:

```bash
abx deploy-resolver --provider <fly|render|vps>
```

The resolver replays events, stores project state, and watches for new blocks.

| Route | Result |
| --- | --- |
| `/t/{chainId}/{address}/{tokenId}` | Token metadata |
| `/c/{chainId}/{address}` | Collection metadata |
| `/api/project/{address}` | Reconstructed project state |
| `/d/{chainId}/{address}` | Project dashboard |
| `/health` | Service health |

Set `ABX_RESOLVER_ADMIN_TOKEN` on the host to enable registration and reindexing. Keep the same value
locally as `ABX_REMOTE_SELF_TOKEN`. It controls the index and cannot sign transactions.

Check progress with `abx status`. The five states are `queued`, `backfilling`, `live`, `stale`, and
`failed`.

```bash
abx status
abx status 0xYourContract
```

The reference resolver assumes one trusted operator. Do not share it with unrelated customers without
adding tenant isolation, quotas, and rate limits.

## Content origins

Project HTML and other active documents must execute separately from the resolver dashboard and
control plane. By default, the reference resolver serves publisher documents with an opaque-origin
CSP sandbox. Scripts and embedding remain enabled, but persistent browser storage and some wallet
connections require a dedicated content domain.

For complete websites, configure a separate domain with wildcard DNS and HTTPS pointing at the
resolver, then set on the resolver and its effects worker:

```bash
ABX_CONTENT_DOMAIN=content.example.net
```

Each collection is served at `https://{chainId}-{address}.content.example.net`, retaining the existing
`/a/`, `/t/`, and `/c/` paths and query parameters. A content host serves only its own collection's
read routes and the ABX runtime; account, dashboard, control, and other collections' routes are refused.
The dedicated domain should hold no application sessions or sensitive cookies. Sibling subdomains
have separate DOM and browser storage, but parent-domain cookies can still be shared. The collection
is the trust boundary: all tokens in it share that collection's origin.

Existing live-view URLs redirect top-level browser navigation to the collection origin. Frames
and server-side downloads receive a restricted marketplace wrapper that frames that origin; its
script also navigates standalone clients that do not send browser fetch metadata.
Image and artifact byte routes redirect without changing committed bytes. The response's `Link`
header with `rel="canonical"` identifies the direct content URL. Service descriptors advertise
`content.domain` and `content.liveViewUrlTemplate`; `abx remote` displays these when available.
On-chain metadata and self-contained on-chain HTML do not change.

For local development, use `ABX_PUBLIC_BASE_URL=http://127.0.0.1:8787` with
`ABX_CONTENT_DOMAIN=localhost:8787` to enable HTTP collection subdomains on the same port. Use HTTPS for public content domains. Configure DNS and certificates before enabling the
setting in production. Changing a content origin starts a new browser-storage namespace and may
require a fresh wallet connection.

## SQLite maintenance

The projection lives at `.abx-self-host/index.db`. Check and reclaim unused pages with:

```bash
abx vacuum
abx vacuum convert
abx vacuum incremental [--pages n]
```

`abx serve` runs bounded incremental cleanup between watch cycles. `abx vacuum convert` is a manual,
one-time full rewrite for an older database with `auto_vacuum: none`. It may need twice the database's
disk size. Run it only when `abx vacuum` recommends it.

## Effects worker

The effects worker uses Chromium to render images and traits for code projects.

```bash
abx effects
abx effects --once
abx render 0xYourContract
abx deploy-effects --resolver-url https://metadata.example.com
```

Set `ABX_EFFECTS_URL` on the resolver for immediate notifications. The worker also sweeps for missed
work.

Separate services need shared storage such as S3/R2, IPFS, or Arweave. Filesystem storage works only
when both processes share the disk. See [Storage](/docs/using-abx/guides/storage).

## Move hosts

```bash
abx migrate 0xYourContract --from <old-resolver> --to <new-resolver>
```

The migration copies offchain values, verifies hashes, and compares results. It does not change DNS
or send a transaction.
