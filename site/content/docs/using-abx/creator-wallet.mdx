---
title: "Creator wallet"
description: "One embedded wallet with automatic gas payment."
---

ABX Services gives each verified account one creator wallet. The API key identifies the account but
cannot sign transactions. The same wallet address applies across EVM networks; each network has its
own balance.

Use `--embedded` for this wallet. `--sponsor` remains an alias for the same automatic payment policy.
When the live provider enables self-payment on a network, ABX uses the wallet's native funds if they
cover the transaction value plus the quoted fees. Otherwise, an eligible zero-value transaction uses
ABX gas sponsorship. A non-zero-value transaction always needs enough native funds for value plus fees.
There is no automatic switch to a different wallet.

The [network table](/docs/reference/deployments) lists sponsorship availability. Wallet self-payment
and sponsorship are separate provider capabilities: check `abx remote abx` and account capabilities.
Self-payment can cover qualified networks without sponsorship, including Ethereum. Sponsorship is
currently offered on eligible Base and Arbitrum networks and their Sepolia testnets.

```bash
abx auth login
abx remote abx
abx deploy --image ./art.png --name "Title" --symbol ART --onchain-uri --embedded --dry-run --json
abx deploy --image ./art.png --name "Title" --symbol ART --onchain-uri --embedded
```

Use the current CLI and refresh its installed skill after upgrading. During a provider rollout,
older providers retain their sponsored-only behavior; recognition by the CLI does not enable a
network or payment mode for an account.

Login provisions or reuses the stable creator wallet. `abx auth wallet` shows its address separately.
Fund that address on the network you intend to use. An ETH balance on Ethereum does not fund Base.
Native fee quotes include execution fees and, on Base, a reserve for estimated L1/operator fees.
Rollup fees can change; the CLI prints the selected payer and fee bounds before submission.

The first creator-wallet operation asks you to approve one agent grant. This single grant permits
wallet transactions, including transferring funds and paying fees. ABX stores it in the operating
system credential store and reuses it for up to 30 days unless revoked. There is no separate grant
for sponsorship or self-payment. Review the network, transaction value, and permanent settings
before sending. [Manage agent access](https://services.abx.io/authorize) to review or revoke grants.

Once an operation is prepared, its payment mode and fee ceilings are fixed. An uncertain submission
is reconciled rather than retried with another payer. Preserve the transaction hash and operation ID;
use `abx auth operation <operation-id>` for read-only recovery.

Bring-your-own signing remains available through `--send`, `--sign`, and `--unsigned`. Run the same
flow on the paired testnet before using a production network.
