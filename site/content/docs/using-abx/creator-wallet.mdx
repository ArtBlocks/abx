---
title: "Creator wallet"
description: "Deploy on eligible networks without bringing a funded wallet."
---

ABX Services gives each verified account one creator wallet. The API key identifies the account but
cannot sign transactions.

The [network table](/docs/reference/deployments) shows where sponsorship is available. Sponsorship may
be limited or paused. Start on a testnet.

The CLI recognizes the sponsored lane on Base, Base Sepolia, Arbitrum, and Arbitrum Sepolia.
Arbitrum sponsorship is in controlled qualification; recognizing a chain does not enable it for
your account. Both the live service descriptor and your account capabilities must allow the chain.

```bash
abx auth login
abx remote abx
abx deploy --image ./art.png --name "Title" --symbol ART --onchain-uri --sponsor --dry-run --json
abx deploy --image ./art.png --name "Title" --symbol ART --onchain-uri --sponsor
```

Login provisions or reuses the account's stable creator wallet. To do that separately, or to show
the address before a sponsored dry run, run `abx auth wallet`.

The first sponsored command asks you to match a code and approve the agent. ABX stores the grant in
your operating system's credential store and reuses it for up to 30 days, unless you revoke it first. You
still review the network and transaction plan in your terminal before each send.

[Manage agent access](https://services.abx.io/authorize) to review or revoke active grants.
Sponsored operations cannot send ETH. If the operation is not eligible, use `--send`, `--sign`, or
`--unsigned`.

If a local RPC fails after submission, do not repeat the transaction. The CLI prints the transaction
hash and operation ID. Check the hash, or run `abx auth operation <operation-id>`.

Run the same flow on the paired testnet before using a production network. Check the network, value,
and permanent settings before approval.
